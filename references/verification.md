# Verify the adaptation

Use one acceptance brief throughout the work. Record the baseline and final evidence with source, viewport, DPR, state, content, theme, motion preference and action sequence. Keep proposed previews distinct from verified implementation.

Test preserved behavior first. Cover the primary action, keyboard activation, focus entry/exit, cancellation and relevant error recovery. Exercise new input during motion and reduced motion. Inspect narrow containers, large text, long content and real asset loading. Test multiple instances and teardown when lifecycle code changed.

Use screenshots or overlays to identify unintended drift from the approved direction. Original-source pixel similarity is not the goal of adaptation. A useful regression check targets preserved geometry or behavior explicitly. Do not manufacture a global visual score for originality or usability.

Inspect hierarchy and content in the rendered component. Check redundant labels, arbitrary badges, decorative section numbers, unnecessary borders, false affordances and copied branding against the host's constraints and approved brief. Make these checks specific to the output; do not replace all expressive work with a generic minimal layout.

Run focused source checks and runtime checks appropriate to the change. Use the host's browser/device workflow, record actual scenarios, inspect console errors and keep evidence. A build confirms compilation, not visible quality. An automated accessibility scan cannot prove complete accessibility. Performance claims require measurements under stated conditions.

The closeout names the working result, transformations that matter, evidence paths, provenance obligations and unverified behavior. Label creative judgment separately from measured behavior and user approval.
