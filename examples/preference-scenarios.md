# Preference scenarios for review

These examples define intended interpretation. They are not live model-evaluation results.

## Vague prompt

Input: "idk this looks too company type, make it me but keep the nice sliding thing"

Interpretation: preserve the observed sliding mechanism. Treat "too company type" as a tentative objection to the current expression. Inspect existing user preferences and product content, find useful references, and propose one concrete direction. Do not assume "make it me" authorizes durable memory or a new personal biography.

Output to develop: one representative component with real content, an identified preserved motion driver, and a short account of the tentative visual choices. Ask about the product only if available context cannot establish what the component should do.

## Scoped correction

Input: "layout's perfect. type is boring. less bounce too"

Interpretation: layout is confirmed. Typography and motion response are the allowed changes. Preserve composition, information, data contract and accepted assets. Check type wrapping because a font change may alter geometry; disclose a necessary dependent adjustment.

Output to develop: revised type treatment and motion response in the same representative state, with interrupted input and reduced motion checked.

## Conflicting references

Input: "this packed dashboard, these playful pictures, but no animations"

Interpretation: density, illustration style and motion are independent dimensions. Retain functional density, use suitable licensed/owned illustrations, and make transitions immediate. Do not average the references into a sparse animated landing page.

Output to develop: one dense usable screen fragment with genuine content, purposeful imagery and a static interaction path.

## Delegated judgment

Input: "you decide, just make it work for a small bakery"

Interpretation: make product-specific decisions from available context. Investigate actual ordering, contact or discovery needs. Choose a coherent direction and reversible defaults, then follow the host's preview/approval requirements. Do not require the user to choose a type scale or animation package.

Output to develop: the primary customer task with relevant content and honest functionality. Unsupported business claims remain absent.

## Material contradiction

Input: "make it exactly identical, but completely different and ours"

Interpretation: distinguish preserved behavior from appearance if the context supports it; otherwise ask one focused question about that conflict. Keep reading and capturing independent evidence. Do not secretly choose adaptation and claim fidelity.
